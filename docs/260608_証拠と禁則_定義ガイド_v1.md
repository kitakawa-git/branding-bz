# 証拠・実績／表現ルール 定義ガイド v1

作成日: 2026-06-08
用途: ID社スタッフの入力作業標準。将来のAI抽出機能のプロンプト仕様書の元ネタ。

## 1. 証拠・実績（ProofPoint）の定義

### 出発点
提供価値（約束）を1つずつ取り、「**なぜそれが本当だと言えるのか？**」と問う。その答えになる事実だけが証拠。

### 採用テスト（1つで判定）
**数字・固有名詞・日付のいずれかを含み、競合がそのままコピーできない事実か。**

| 判定 | 例 |
|---|---|
| ❌ 証拠ではない | 「高品質なサポート」「豊富な実績」「お客様に寄り添う」 |
| ✅ 証拠 | 「利用者満足度92%（2025年調査）」「導入実績120社」「○○病院で運用3年」 |

### source_type別の問い
| 種別 | 問い |
|---|---|
| 実績（jisseki） | 何件・何年・どの規模でやってきたか？ |
| データ（data） | 測定できた成果の数値は？（出典・時期・nを必ず添える） |
| 事例（jirei） | どの顧客で、何が、どう変わったか？ |
| 顧客の声（voice） | 誰が（属性）、何と言ったか？（原文のまま） |
| 受賞（award） | 第三者の評価・認証・表彰は？ |

### 運用ルール
- 出典と時期を必ず記録する（古い証拠は更新時に見直す。目安：evidence_dateから2年で要再確認）
- 紐づけ先の提供価値を選ぶ。どの約束にも属さない全社的な事実は「全般」でよい
- **証拠が1つも見つからない提供価値は、約束の側を疑う**（→ クライアントとの議論の起点になる。これ自体が成果）

## 2. 表現ルール（GovernanceRule）の定義

### 出発点
ルールは発明するものではなく、**既に起きた修正・違和感の言語化**。原料は3つの問いで掘る。

| 問い | rule_type |
|---|---|
| 社長・担当者が原稿チェックで毎回直す箇所はどこか？ | tone_rule（トーン） |
| 競合は言いそうだが、うちは絶対に言わないことは何か？ | claim_rule（主張）／discouraged_expression |
| 言ったら法律・信頼の問題になる表現は何か？ | compliance_rule（コンプラ） |

単語レベルの言い換え（「利用者」→「お客様」等）は brand_terms に。**ルール（なぜ・どう語るか）だけをここに入れる。**

### severityの判定（単純に2択）
- **block（絶対遵守）**: 法規制・業界規制由来（薬機法・景表法・効果保証の禁止など）。違反したら事故になるもの
- **warn（原則遵守）**: らしさ・トーン由来。文脈によっては破ってもよいもの
- info はメモ用途。迷ったら warn

### 運用ルール
- **NG例とOK例を必ずセットで書く**。禁止だけではAIも人も行き場を失う。OK例が言い換えの方向を与える
- 1ルール1論点。「平易に書き、かつ断定しない」のような複合ルールは2つに分ける
- scopeは迷ったらglobal。特定の提供価値・対象顧客にだけ効くルールのみ絞る

## 3. 入力フロー（人間に白紙から書かせない）

1. **抽出**: クライアントの既存資産（Webサイト・パンフ・過去の制作物・ヒアリング録）から、AIに証拠候補・ルール候補を抽出させる
2. **判定**: ID社が上記テストで採否を判定し、事実確認（数字・出典）をクライアントに依頼
3. **承認・投入**: 確認が取れたものだけ管理画面に登録。未確認の数字は登録しない（AIが創作の根拠に使ってしまうため）

> 原則: 人間の仕事は「定義」ではなく「判定」。

## 4. アンチパターン（やってはいけない入力）

- 形容詞だけの証拠（「高い技術力」）→ 採用テストで弾く
- 出典のない数字 → 事実確認が取れるまで投入しない
- NGワードの羅列だけの表現ルール → brand_termsへ。ここはルールを書く場所
- 1社に証拠20件 → AIへの注入が薄まる。各提供価値に2〜3件、全社で10件程度が目安
- 「全部block」→ blockは法規制由来のみ。何でもblockにするとAIの出力が硬直する
