## 2. 本日（2026-07-15）完了した作業 — すべて本番反映済み

### 2-1. canonical / og の脱落を修正（致命バグ）★最重要
**原因**: `app/(marketing)` → `app/(site)` のルートグループ移植時に、各ページの `alternates.canonical` と
`openGraph` が脱落（title/description だけコピーされた）。結果、本番で `/plan` `/faq` `/features`
`/news` 等の canonical が **トップページ（`https://branding.bz`）を指していた**＝「私はトップの複製です」と自己申告。

**修正**: 全公開ページに canonical + og を復元。
- `(site)`: `/plan` `/faq` `/features` `/news` `/news/[slug]`（generateMetadata で article/publishedTime）
- `(marketing)`: `/terms` `/privacy-policy` `/tokusho`（layout を server 化して対応）
- `/tools/*` は元々正常（専用 layout.tsx で明示上書き済み）＝触っていない

**検証**: 本番 curl で全12ページの canonical が自己参照になったことを確認。トップ落ちゼロ。

### 2-2. スマート名刺 `/card/[slug]` を noindex 化 ★個人情報保護
顧客企業の社員の氏名・役職・メール・電話が載るページ。QRで手渡す前提で、検索流入は不要。
**2026-07-15 時点で `site:branding.bz/card` = 0件（未インデックス）だったため、載る前に塞げた**（一度載ると消すのは困難）。
- `robots: { index:false, follow:false }` を metadata で設定（`/mypage` `/offline` も同様）
- **robots.txt では Disallow しない**（Disallow するとクローラが noindex タグを読めず「URLだけインデックス」の最悪状態になる。クロールは許可し meta で伝えるのが正解）

### 2-3. sitemap.ts の正常化
- `new Date()` を全廃（毎デプロイで全ページが「更新された」と嘘をつく状態を解消）→ 静的ページは固定日付
- ニュース記事8本を Supabase から動的取得。**URL数 13 → 21**
- lastmod がユニーク複数値になった（全ページ同一の病気は解消）

### 2-4. GA4 タグ設置 ★計測の配線
`@next/third-parties` の `GoogleAnalytics` を root layout に追加（測定ID `G-CQBED1RNV2` ハードコード）。
**3か月間プロパティは存在したがタグ未設置で計測ゼロだった**。
**2026-07-15、GA4 リアルタイムでアクセスがカウントされることを確認＝配線完了。**

### 2-5. GSC 操作

## 6. 技術メモ

- **メタデータ継承**: Next.js App Router は親→子でマージ継承。子が `alternates`/`openGraph` を明示しないと
  ルート layout の値（＝トップのURL）を引き継ぐ。`'use client'` ページは `export const metadata` 不可 →
  layout.tsx を server の metadata wrapper にする（/contact, /tools/* が既存パターン）。
- **ビルド**: `next build --webpack` 必須（serwist/PWA と Turbopack が衝突）。外さない。
- **Vercel env**: 2026-07-15 に `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` を
  Preview にも追加済み。**`SUPABASE_SERVICE_ROLE_KEY` は意図的に Production のみ**（RLS を越える鍵を
  公開URLの Preview に置かない方針）。→ 施策 B で route を lazy init 化すれば Preview は service キー無しで通る。
- **GA4 測定ID**: `G-CQBED1RNV2`。env 化していない（公開値＝ハードコードで実害なし）。

## 9. 検証プロトコル（このプロジェクトの鉄則）
1. **canonical/メタは本番 or Preview の生HTMLを curl で確認**。DevTools（JS実行後）で見ない。
   ```bash
   curl -s "https://branding.bz/<path>" | grep -oiE '<link rel="canonical"[^>]*>'
   ```
   期待: 各ページが自己参照。トップのURLが出たら失敗。
2. sitemap: `grep -c '<loc>'`（21）、`grep '<lastmod>' | sort -u`（複数値）。
3. GA4: 本番反映後にリアルタイムでアクセスがカウントされるか。
4. 「実装した＝直った」と判断しない。ローカルビルド・過去資料・自分の記憶を疑う。
