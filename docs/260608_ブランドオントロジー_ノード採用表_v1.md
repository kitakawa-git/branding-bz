## Step 0 の最小仕様

- `proof_points` テーブル新規作成：company_id ＋ 参照FK（どのBenefit/Valueの証拠か）＋ 本文・出典
- `governance_rules` テーブル新規作成：company_id ＋ 適用範囲 ＋ ルール本文 ＋ NG例/OK例
- 関係グラフ（element_relations）はStep 1まで作らない。ただし参照FKはStep 0で必須（FKがないとAIが該当の鎖を選べず、ただのリストになる）
- 用途：コピー生成・草案生成プロンプトに該当データを参照させ、平均値化を防ぐ

## 合意済みの設計原則（経緯メモ）

1. グラフであってチェーンではない（N:N、関係はelement_relationsで表現）
2. グラフは「推論に使う関係」だけを持つ。全ブランド要素を入れる場所ではない
3. 対外系統・対内系統・事業系統の3系統＋系統横断のconflictsWith
4. 対内系統の終点はDBノードではなく測定データ（timeline_postsへのelement参照で行動一致を実測）
5. 「ブランド経営判断支援AI」への転換は製品戦略の論点として保留。現時点の定義は「ブランド情報を構造化し、草案生成・整合性チェック・浸透支援に使うSaaS」
6. 編集権限はID社（スーパー管理画面）、閲覧はクライアント可。データは各社の理念体系テーブルに置きRLSで管理
