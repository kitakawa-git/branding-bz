# sync-status（コード案件／非開発案件 両対応）

## 0. まず分岐を判定する
作業フォルダで `git rev-parse --is-inside-work-tree` を実行する。

- **成功（git リポ）→ A: コード案件モード**
- **失敗（git でない＝Drive の案件フォルダ）→ B: 非開発案件モード**

判定結果を最初に一言report してから進む。

---

## A. コード案件モード（~/dev/<repo>）

### A-0. 事前同期
`git pull --ff-only`。分岐（diverged）したら作業を止めてユーザーに報告する。無理に merge/push しない。

### A-1. 対象ファイル検出
`docs/*-PROJECT-STATUS.md` を検出。複数ならユーザーに確認。無ければ「作成するか、パスを指定してほしい」と報告して停止（別名で勝手に作らない）。

### A-2. 現状確認
- `git log --oneline -10`
- 直近差分: コミット2つ以上なら `git diff --stat HEAD~1`、1つだけなら `git show --stat`
- `git status -s`（未コミット把握）
- TS プロジェクトのみ `npx tsc --noEmit`／該当時 `console.log` 残数

### A-3. 更新
既存の見出し構造に合わせて追記する（存在しないセクションを勝手に作らない）。
残タスク（`[ ]`→`[x]`・数値更新）／意思決定ログ／教訓・技術メモ／実装履歴／コンポーネント・画面・DB／開発状態（ブランチ・PR・デプロイ・マイグレーション・負債）／メタデータ（最終更新日・更新者）。

### A-4. commit & push（未 push は未完了）
- `git add docs/<PREFIX>-PROJECT-STATUS.md`（ステータスのみ明示ステージ。WIP を巻き込まない）
- `git commit -m "docs: <PREFIX>-PROJECT-STATUS 更新（/sync-status）"`
- `git push`
- **push が失敗したら「完了」と報告しない。** 失敗理由（認証なし／サンドボックス制限／non-fast-forward／upstream 未設定）を明示し、ユーザーのターミナルで実行するコマンドを添える。
- feature ブランチ上ならその旨を明記（main 反映は PR マージ後）。

## B. 非開発案件モード（Drive の案件フォルダ）

### B-1. 対象ファイル検出
**フォルダ直下**の `<CODE>-PROJECT-STATUS.md` を探す（`docs/` ではない）。
複数あれば確認。無ければ、CLAUDE.md 記載の CODE を使って規約名で新規作成する（別名で作らない）。

### B-2. 現状確認
git は使わない。代わりに次を見る。
- フォルダ内の最近更新されたファイル（成果物・資料）
- このセッションの会話内容（決定事項・次にやること・保留）

### B-3. 更新
既存の見出し構造に合わせて追記する。
現状サマリー／完了／進行中／保留・未決／重要な決定事項／参照／履歴。
テーマ別のサブステータス（例: SEO・freee 照合）がある場合、それはサブ記録。プロジェクト正本はこのファイル。

### B-4. 保存確認（push は不要）
- Drive の案件フォルダに保存し切る。outputs（スクラッチパッド）に置いたまま完了としない。
- **保存後に本物フォルダのフルパスを `ls` して実在を確認**してから完了と報告する。
- git 操作は行わない。Drive 保存＝共有完了。

## 出力サマリ
```
## ステータス更新完了
- モード: A(コード) / B(非開発)
- プロジェクト: <CODE>（プロジェクト名）
- 保存先: <フルパス>（ls 確認済み）
- ※Aのみ ブランチ / push: main（pushed 済み）など。未pushならその旨を明記
- 完了にしたタスク / 新規タスク / 新規教訓: ○○
- ※Aのみ TSエラー: N件→M件 ／ console.log: N→M
```
push が未完了のときは見出しを「## ステータス更新（未push・要ユーザー対応）」に変え、必要なコマンドを添える。

## 注意事項
- 1プロジェクト＝1ステータスファイルを上書き更新（日付つきコピー・別名を作らない）。
- 別立ての「引き継ぎ」ファイルを作らない。ステータスが引き継ぎを兼ねる。
- CLAUDE.md との役割分担: コーディングルール・運用ルール→CLAUDE.md／進捗・教訓・決定事項→ステータス。
- 既存の見出し構造に合わせる。存在しないセクションを勝手に作らない。
