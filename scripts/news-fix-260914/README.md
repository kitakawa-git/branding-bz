# §7 ニュース記事 文言修正（2026-09）

対象: Supabase `public.news` の10記事。**本番データは未変更です。**

## 実行順序

| 順 | ファイル | 内容 | 変更 |
|---|---|---|---|
| 1 | `01_backup_and_precheck.sql` | 退避表 `news_backup_260914` を作成し、件数・重複・ハッシュを確認 | データ変更なし（表の追加のみ） |
| 2 | `02_update.sql` | 10記事を更新（1トランザクション） | **変更あり** |

| 4 | `04_restore.sql` | 戻すときだけ実行 | **変更あり** |

- 01 の「backup_rows」が **10** でなければ 02 を実行しない。
- 02 は途中で条件を満たさなければ `raise exception` で全体が巻き戻る。
- 03 の「古い表現が残っていないこと」は全項目 **0** が正常。
- 03 の `note_count` は3記事とも **1** が正常。

## 中止される条件（02）

1. 退避表が無い、または10件でない
2. 01 実行後に本文・タイトル・summary が変わっている（他セッションの編集）
3. 置換対象の文字列が見つからない（既に適用済みの可能性）
4. 置換後に古い文字列が残っている
5. 「ブランド情報に反映する操作を指します」の注記が2回以上入っている

## 復元の条件（04）

`news_after_260914`（03 で作成）と現在の内容を照合し、02 実行後に誰かが編集していたら中止します。

## 変更する列

`title` / `summary` / `body` / `updated_at` のみ。
`slug` / `published_at` / `is_published` / `category` / `id` は変更しません。

## 日付

訂正日・確認日は `to_char(now() at time zone 'Asia/Tokyo','YYYY-MM-DD')` で、**実行した日**が入ります。

## 後片付け

問題がないと確認できたら、退避表を削除してください。
```sql
drop table if exists public.news_after_260914;
drop table if exists public.news_backup_260914;
```
